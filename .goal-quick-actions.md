- REUSE primitives (don't duplicate): `addTagToThreads`, `setThreadTag`, `markRead`, `moveThreadsToFolder`, `archiveThread`, `snooze(id,subj,dueAt)`, `watch(...)`, `draftFromTemplate`; folders/tags via `loadFolders`/`loadTags`.

## Build
1. **Model + localStorage** (`augment.quickActions.v1`): `QuickAction = {id, name, shortcut, steps[]}`. Step types: tag, untag, moveToFolder, archive, delete(Trash), markRead, markUnread, star, unstar, snooze(preset), notifyWhenReplied, and compose: reply/replyAll/forward/newMail (optional `templateId` + `sendWithoutReview`).
2. **Manager**: the sidebar view → list (add/edit/duplicate/delete/reorder) + inline editor: name, shortcut via `KeybindCapture` (flag conflicts), ordered step list (add/remove/reorder), value pickers from live tags/folders/templates/snooze-presets.
3. **Execution** (`augment.tsx`): target = selection if any, else the open email; no-op + Activity notice if neither. Mailbox steps run on ALL targets, in order, continue-on-error, each logged (order matters: tag before move). A compose step runs ONCE on the primary (open/first) email: opens the composer prefilled; with a template + `sendWithoutReview` it auto-sends silently.
4. **Composer**: New/Reply/Reply-all/Forward; To/Cc/Bcc/Subject/Body; replies quote the original + set In-Reply-To/References to thread correctly; attachments (multipart MIME, file picker); Send (`messages.send`) + Save-draft (`createDraft`).
5. **Triggers**: per-action shortcut (anywhere in the main window), a row right-click "Quick Actions ▸" submenu, and ⌘K palette entries.

## Done when
- Create/edit/reorder/duplicate/delete Quick Actions with recorded shortcuts (conflicts flagged); fire via shortcut, submenu, and ⌘K.
- A multi-step action runs in order on the right target(s); compose opens prefilled or auto-sends a templated reply; Send/Draft/attachments work and replies thread correctly.
- `tsc --noEmit`, `cargo check`, `vite build`, `vitest run` all pass; no regression to triage, tags, assistant, rules, templates.

## Constraints
- Match the codebase's conventions + comment density; reuse existing methods, `KeybindCapture`, templates.
- Mark destructive steps (delete, auto-send) clearly; never auto-send without template + `sendWithoutReview`.
- Keep the scope/re-consent change explicit + graceful. Verify by building each phase; don't claim done until all four checks pass.
